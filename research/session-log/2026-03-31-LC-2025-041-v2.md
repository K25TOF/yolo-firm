**Optimist:** ## LC-2025-041 — Optimist Turn

### Interpretation of the Problem

The static 09:35 entry is pattern-blind. It enters all 192 trades at the same moment regardless of what the price path has done since open. The core insight is that patterns 2 and 3 both require a **completed pullback** before the entry signal is valid — and pattern 1 (straight runner) is the only case where early entry is genuinely justified. Pattern 4 looks identical to patterns 2/3 in the first few bars, which is the hard discrimination problem.

The good news: we have full 1-min bar data from 09:30 to exit for all 192 trades. That means the price path from open to 09:35 — and beyond — is observable. We can extract features that characterise the **shape** of that path and map each trade retrospectively to a pattern label. That label assignment is the analytical prize.

---

### Feature Extraction Proposal

All features are computable from existing bar data. I'm proposing three feature families:

---

#### Family 1: ORB Relationship Features
*Purpose: Where is price relative to the ORB high at each bar?*

**F1.1 — ORB Gap at Open**
`orb_gap = (open_price - orb_high) / orb_high`
- Positive: opened above ORB high (classic gap-up)
- Negative: opened below ORB high (needs to work back up)
- This immediately separates pattern 3 (gap → tank, orb_gap likely small or negative) from patterns 1/2

**F1.2 — ORB Retest Depth**
`retest_depth = min(bar_low[570:574]) - orb_high) / orb_high`
- Minimum low in the ORB window relative to ORB high
- For pattern 2: price spikes then pulls back — this value will be negative
- For pattern 1: price never pulls back — this value stays flat or positive
- For pattern 3: initial bars show immediate decline from open

**F1.3 — Price Position at 09:35 Relative to ORB High**
`entry_orb_ratio = (entry_price - orb_high) / orb_high`
- Already computable from existing data
- This is the distance the trade starts from the breakout level

---

#### Family 2: Pre-Entry Path Shape Features
*Purpose: Characterise what happened in the bars BEFORE 09:35 entry*

I propose computing these over bars 570–574 (the ORB window itself, 09:30–09:34):

**F2.1 — Path Slope (Linear Regression Slope on closes[570:574])**
`slope_orb = linregress(t=[0,1,2,3,4], y=bar_close[570:574]).slope / orb_high`
- Positive and steep: straight runner candidate (pattern 1)
- Positive then negative (non-monotone): spike-and-pullback candidate (pattern 2)
- Negative: tank candidate (pattern 3 or 4)

This single feature distinguishes the *direction* of the approach to entry.

**F2.2 — High-to-Close Ratio in ORB Window**
`hc_ratio_orb = (max_high[570:574] - close[574]) / (max_high[570:574] - min_low[570:574])`
- Near 0: price closed near the high of the ORB window — bullish close, straight runner more likely
- Near 1: price closed near the low — pullback in progress, patterns 2/3/4 candidates
- This is the **candlestick body position** equivalent for the window

**F2.3 — Recovery Indicator**
`recovery_ratio = (close[574] - min_low[570:574]) / (max_high[570:574] - min_low[570:574])`
- Complement of hc_ratio: near 1 means price closed near window high after touching window low
- High recovery + meaningful wick = **completed pullback signal** — the core of patterns 2 and 3
- This is the most important feature for the question at hand

---

#### Family 3: Post-Entry Path Validation Features
*Purpose: Retrospectively label what actually happened — used to build the ground truth pattern label*

These use bars 575 onward and are NOT available at entry time, but they define the outcome label:

**F3.1 — MFE/MAE Path Timing**
`mfe_bar = first bar where (high - entry_price)/entry_price ≥ 0.05` (5% threshold)
`mae_bar = first bar where (low - entry_price)/entry_price ≤ -0.05`
- Pattern 1: mfe_bar comes early (bars 575–580), mae_bar never triggers or comes late
- Pattern 2/3: mfe_bar comes after an initial dip — mae_bar fires first, then mfe_bar (or neither)
- Pattern 4: mae_bar fires early, mfe_bar never triggers
- **The relative ordering of mae_bar vs mfe_bar is the ground truth discriminator**

**F3.2 — Early Drawdown Before Gain**
`early_dd = min(bar_low[575:580] - entry_price) / entry_price` (first 5 bars post-entry)
- Pattern 1: near zero or positive
- Pattern 2/3: negative then recovers (early_dd < 0 but MFE_30bar ≥ 10%)
- Pattern 4: negative, stays negative

**F3.3 — MFE_30bar Already Available**
The 35% that reach ≥10% MFE and 67% that hit -10% stop are pre-computed. Cross-tabbing pattern labels against these is the validation step.

---

### Pattern Label Assignment Logic

Using the features above, I propose this labelling rule:

| Pattern | Defining Feature Combination |
|---|---|
| 1 — Straight Runner | slope_orb > 0 AND hc_ratio_orb < 0.3 AND early_dd > -0.02 |
| 2 — Spike-Pullback-Recover | hc_ratio_orb ≥ 0.5 AND recovery_ratio ≥ 0.6 AND orb_gap > 0 |
| 3 — Tank-Floor-Reversal | orb_gap < 0.02 AND slope_orb < 0 AND recovery_ratio ≥ 0.6 |
| 4 — Failed Runner | early_dd ≤ -0.05 AND MFE_30bar < 0.05 |

Pattern 4 is the only label that requires a post-entry feature (early_dd). That's intentional — at entry time, pattern 4 is **indistinguishable** from 2 or 3. This is the core problem. The pre-entry features (F1, F2) can narrow the candidate pool; F3 confirms the label retrospectively. The signal design question then becomes: **which pre-entry feature combination has the highest forward probability of being pattern 1, 2, or 3 rather than 4?**

---

### Entry Signal Logic by Pattern

**Pattern 1 — Enter immediately at 09:35 (current logic is correct)**
Condition: `slope_orb > 0 AND hc_ratio_orb < 0.25`
Rationale: Price is still running, no pullback detected. Waiting costs fill price.

**Pattern 2/3 — Wait for recovery confirmation, enter on breakout of recovery bar**
Condition: `recovery_ratio[bar B] ≥ 0.70 AND bar_close[B] > bar_close[B-1] AND bar_vol[B] > vol_ema[B]`
Entry: `bar_open[B+1]`
Rationale: Enter the first bar where price closes near its high after the pullback — this is the reversal bar. The volume confirmation distinguishes genuine reversal from a dead-cat bounce.

**Pattern 4 — Do not enter**
Condition: if early bars show `slope_orb < 0 AND recovery_ratio < 0.35 at 09:35`, flag as Pattern 4 risk. Entry deferred until recovery_ratio clears 0.70. If it never clears by bar 590 (10:00), skip.
